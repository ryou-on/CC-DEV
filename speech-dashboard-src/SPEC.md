- 構成: React + Tailwind CSS + Recharts / Firebase Auth・Firestore / Cloud Run + FFmpeg
- 公開先（予定）: https://cc-dev-ps7.web.app/speech-dashboard/
- 共通仕様: /Users/lobby/.codex/standards/kikaku7-app-development-standard.md v1.0.0

## 1. 到達点
APIキー不要の明示的なデモと、実音声を処理するサーバー経路を用意する。実音声の処理をデモで代替しない。ローカルはJSON保存、本番はFirebase認証・App Checkを検証しAdmin SDKからFirestoreへ保存する。画面は原則App.jsx一枚に集約、集計・API・サーバー責務を別ファイルにする。

## 2. 入力と分類
m4a / wav / mp3 / mp4 / webm / ogg / flacを複数ドラッグ&ドロップ、またはファイル選択。Phase 1では1ファイル20MB・1区間10分以内。ファイルごとに参加者ID、Day、セッションID、Main/Room、Room名、録音上の開始秒・終了秒・セッション時刻への補正秒を編集できる。同一ファイルから複数区間を追加可能。終了空欄は末尾（上限10分）。セッションIDはDay内で一意。参加者IDは日をまたいで統一し、表記ゆれは利用者が修正する。

MainとBOの切替は自動推測しない。同じMainを複数担当者が録音した場合は代表1本を選ぶ。SHA256＋所有者＋分類＋切り出し条件で同一入力の再登録を防ぐ。異なる録音機の波形による重複統合・自動同期・音源分離はPhase 2以降。

## 3. 分析定義
- FFmpegで切り出し・16kHzモノラルPCM化。silencedetect（-35dB、0.35秒）により非無音区間を推定。雑音を発話と誤検知し得るため全画面で推定値と明記。
- 同一録音で0.7秒以内の短い間をつなぎ1発言とする。発話秒数は非無音区間の和であり、つないだ無音の長さを含めない。
- 発話率 = 個人の発話秒数 / 選択範囲の全参加者の発話秒数 × 100。0秒なら0%。同時発話は各話者に計上するため経過時間とは異なる。
- 発言回数 = 上記連続区間の個数。平均発話長 = 発話秒数 / 発言回数。無発話者も取り込み済みなら0として表示する。
- タイムラインはDay＋セッション＋Room別。時刻 = 元音声秒 + 補正秒。異なる日・セッションを同じ時間軸へ混ぜない。
- 比較軸: 個人、ルーム（Main含む）、日。フィルタ: Day、Main/Room、参加者、発言タイプ、要確認。

## 4. 外部API
OpenAI whisper-1 + verbose_json + segment timestampsで文字起こしする。長区間は300秒PCMチャンク（約9.6MB）に分割し元時刻へ戻す。モデルは時間情報の契約を固定するためPhase 1でwhisper-1に限定。発言区間と重なる文字起こしセグメントを最大重複の発言へ一度だけ割り当てる。文字起こしの境界と実発話の境界は完全には一致しない。

Jevは公式TypeSafeエンドポイント https://api.typesafe.ai/v1/systemone を使う。stateに発言本文、questionsにChoice（質問/回答/提案/説明/同意/反対・懸念/確認/雑談/その他）、Score（0反応なし〜4議論を前進させる提案）、Noul（情報・意見を引き出す質問）を送る。Scoreは小数を保持。質問判定はnoul >= 0.5。ChoiceまたはScore confidence < 0.65 は要確認。本文なし・API失敗時は「未分析」とし、その他や0点に置換しない。API失敗は発話量・文字起こしを失わせず部分完了として保存する。再試行は保存済み音声がないため再アップロードで行う（同じ結果IDを更新）。モデル・ルーブリック版を保存する。

## 5. 画面
ヘッダー、取り込み、4つのKPI、Recharts比較グラフ、集計表、セッション別タイムライン、文字起こし・分類一覧。デモデータと実データは混ぜない。読み込み中、保存失敗、空データ、API未設定を表示する。
アプリ名から使い方、バージョンからリリースノート。両モーダルは閉じる・背景クリック・Escape・フォーカス復帰対応。使い方にはホームへ戻る。目安箱を実装。診断コピーは許可済みコード・件数・版・URL pathnameだけを含み、氏名・本文・ファイル名・キーを含めない。

## 6. 保存とAPI
- POST /api/speech/recordings: multipart（file, metadata JSON）、同期処理。処理中表示、結果保存後応答。
- GET /api/speech/recordings: 所有者の結果を取得。
- POST /api/speech/feedback: 匿名化注意表示後送信。
- POST /api/speech/analytics: 日別匿名アクセス集計。
- Firestore speechUsers/{uid}/recordings/{hash}: メタデータ・処理状態・指標・発言配列。10分/最大300発言/本文上限で1文書サイズを制限。
- apps, changelog, analytics, feedback はサーバー専用。登録・更新管理スクリプトを用意。クライアントからの直接書き込みは禁止。
- ローカルの .local-data/ はGit・Hosting・Dockerから除外。音声は一時ディレクトリへ置きfinallyで削除。再生・音声の永続保管は対象外。

## 7. 認証・運用
ローカル開発は127.0.0.1にのみバインド、外部Origin拒否、明示的なlocalモード。Cloud RunではFirebase ID token、speechAnalystカスタムクレーム、App Check必須。ローカル認証省略がCloud Runに混入したら起動拒否。Secret ManagerからOPENAI_API_KEY / JEV_API_KEYを環境変数注入し、フロントへ公開しない。外部API URLを利用者入力から受け付けない。
本番フロントはVITE_API_BASE_URLに設定したCloud RunのHTTPS URLへ直接接続し、許可OriginのみCORS対応する。Firebase Hosting経由のAPI呼出は60秒制限があるため使わない。Cloud Runは同期MVP、timeout 900秒、concurrency 1、max-instances 1を推奨。処理は応答前に完結させ、応答後バックグラウンド処理に依存しない。長時間録音・大人数運用はStorage直送＋Cloud Tasksへ移行する。サーバー側タイムアウト・ファイル数/サイズ・処理数上限とレート制限を設ける。

## 11. タイムテーブル照合の追加要件（2026-10-02追記）

本節は実運用の追加要件。現在のv0.1.0で実装済みという意味ではなく、次の機能版の設計基準とする。実スプレッドシートの列構成・録画開始時刻の取得方法を確認して取り込み実装を確定する。

### 11.1 1日分の構成

- メイン: その日共通のクラウド録画・録音を1つの原本として扱う。午前の説明、各回の振り返り、終了時のまとめなど複数の予定から同じ原本の別区間を参照する。予定ごとに原本を重複アップロード・重複計上しない。
- ブレイクアウト: 1日に数回開催し、各回4部屋。録画は部屋・開催回ごとに個別に存在する。Room Aの第1回と第2回を別セッションとして識別する。
- 録画の単位と分析する予定の単位を分離する。1原本から複数予定を参照でき、1予定には参加者別の複数音声を関連付けられる。
- クラウド録画URLを受け付ける場合も、URLを分析済み音声と見なさない。認証・ダウンロード可否を確認する。最初はダウンロード済みMP4/M4A等を入力とする。

```text
研修 / Day 1
  Main共通原本 ─┬─ オープニング区間
                ├─ 第1回後の全体共有区間
                ├─ 第2回後の全体共有区間
                └─ まとめ区間
  ブレイクアウト第1回 ─ Room A / B / C / D の各原本
  ブレイクアウト第2回 ─ Room A / B / C / D の各原本
  ブレイクアウト第3回 ─ Room A / B / C / D の各原本
```

### 11.2 タイムテーブルを表示・集計の基準にする

表示例（以下の時刻・名称は仮の例で、実際の予定ではない）:

| 予定時刻 | 内容 | Main | Room A | Room B | Room C | Room D |
|---|---|---|---|---|---|---|
| 09:00–09:30 | オープニング | 共通原本の区間 | — | — | — | — |
| 09:30–10:00 | 第1回ワーク | — | 第1回A | 第1回B | 第1回C | 第1回D |
| 10:00–10:15 | 全体共有1 | 共通原本の区間 | — | — | — | — |
| 10:15–10:45 | 第2回ワーク | — | 第2回A | 第2回B | 第2回C | 第2回D |

最初にタイムテーブルを表示し、各セルに「未割当／紐付け済み／分析中／完了／要確認」を表示する。予定を選択するとその予定の発話量・発話内容・時間軸を表示する。素材がない予定は0発話とせず「録音未登録」とする。

### 11.3 スプレッドシート取り込み

- 実シート確認後に列対応を定義する。最小項目は日付またはDay、開始時刻、終了時刻、内容、Main/ブレイクアウト、開催回。必要に応じてRoom、ワークのテーマ、担当者を取り込む。
- シートがブレイクアウト1回を1行で表す場合は、4部屋の分析枠へ展開する。部屋ごとに4行ある場合は重複展開しない。インポートプレビューで確認する。
- 休憩、移動、運営説明等の分析対象外の予定を保持し、集計から除外できるようにする。
- 開始/終了の不正、同じ部屋の予定重複、Day/日付の欠落、開催回の曖昧さを検出する。同時開催の異なる4部屋は正しい重なりとして扱う。
- 初期対応は実シートに合わせたCSVまたはXLSXインポートを想定。Google Sheets直結と更新同期は共有URL・権限・形式の確認後に決める。元シートへの書き込みは行わない。
- 元行の識別子と取り込み版を保持し、再取り込みで予定・結果を二重登録しない。時刻や開催回の変更時は既存の割当を自動で上書きせず、差分を表示する。

### 11.4 実録音との時刻合わせ

予定開始時刻と実際の録画開始時刻を別フィールドにする。録画開始時刻は、利用できるZoom情報やファイル名から候補を提示し、利用者が確認・補正できるようにする。根拠がない場合は手動指定とし、予定開始時刻を録画開始時刻だと推測しない。

```text
音声上の開始秒 = 分析対象の実開始日時 − 原本の録画開始日時
音声上の終了秒 = 分析対象の実終了日時 − 原本の録画開始日時
予定内相対秒   = 音声上の秒 + 原本の録画開始日時 − 予定開始日時
```

予定時刻から区間の候補を作り、実際に開始が遅れた・終了が延びた場合は実区間を補正する。予定との差を保持する。原本の範囲外、欠損区間、録画の中断は「要確認」とする。中断前後の別ファイルにはそれぞれ開始日時を持たせ、連続していると仮定しない。

### 11.5 保存モデルの拡張

| 単位 | 主なフィールド | 目的 |
|---|---|---|
| training | trainingId, title, timezone | 複数研修の混同防止 |
| scheduleBlock | blockId, trainingId, day, plannedStart, plannedEnd, title, kind, round, room, sourceRowId, importVersion, excluded | 予定・開催回・部屋の識別 |
| recordingAsset | assetId, trainingId, day, origin(cloud/local), audioLayout(separate/mixed/unknown), hash, recordedAt, duration, participantId? | 同じ原本の一意管理 |
| recordingBinding | bindingId, blockId, assetId, clipStart, clipEnd, alignmentStatus, adjustmentReason | 原本と予定の多対多対応 |
| utterance | assetId, sourceStart, sourceEnd, blockId, participantId?, analysis | 発言と元音声位置の追跡 |

日別集計では、同じ原本・同じ音声トラックの同一区間を複数の予定から参照しても重複計上しない。部屋ごとに別の原本がある同時発話はそれぞれ計上する。結果のキャッシュは原本・区間・処理版で管理し、表示上の予定名変更だけで外部APIを再実行しない。

### 11.6 個人別分析と混合音声

参加者別音声なら参加者IDへ直接対応付ける。メインやBOの録音が全員の声を含む1本の場合は、個人別分析の前に話者分離と参加者名の確認が必要。ファイル名を1人の参加者名と見なし、部屋全体の発話をその人へ加算してはならない。

混合音声は話者A/B等の暫定ラベルと「氏名未確認」を保持する。異なる部屋・開催回で同じ話者Aラベルが出ても同一人物とは見なさない。氏名確定前は部屋・予定単位の分析のみを表示し、個人比較への混入を防ぐ。現在のv0.1.0は参加者別音声向けであり、この混合音声対応は未実装。

### 11.7 追加する比較

- 同じ開催回でRoom A〜Dの発話量・発言タイプ・質問傾向を比較。
- 同じ人の第1回→第2回→第3回の変化を比較。参加者名の確認と参加部屋の変更に対応。
- 同じテーマ/ワークについて日別比較。名称だけで同じテーマと断定しない。
- MainとBOは別集計を標準とし、全体合算は明示的な切替にする。
- 予定時間、実際の分析時間、発話時間を別表示。時間が異なるワーク同士は総量と1分あたり回数を併記。

### 11.8 追加受入条件と実装順序

1. 実タイムテーブルの列・録画情報を確認し、1日分の予定表をプレビューできる。
2. 同日Main原本1つを複数予定へ紐付け、各開催回の4部屋の原本を個別に紐付けられる。
3. 時刻不明/録音なし/予定外/音声範囲外は要確認となり、分析済みと表示されない。
4. 開催回フィルタ、予定軸のタイムライン、同一回4部屋比較を実装。
5. 既存20MB/10分上限を超える日次クラウド原本に対応するため、原本保管・長時間ジョブ・分割処理を追加。v0.1.0の短区間APIに日次原本をそのまま渡せるとはしない。
6. 混合音声がある場合に話者分離・氏名確認・個人比較への反映を実装し、実音声で評価。

現時点で不足している確認資料: 実スプレッドシート、録画開始時刻の所在、Main/BO音声が参加者別か混合か。
