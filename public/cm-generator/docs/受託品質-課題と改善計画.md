# cm-generator 受託品質化 — 課題一覧と改善計画

- 調査日: 2026-10-15
- 起点: `origin/main` の `public/cm-generator`（コミット `c571510`）。HANDOVER は「main 未マージ」と書いているが、調査時点でコードと歯科医院向け CM 4本は `origin/main` に入っている
- 自己申告バージョン: v0.1.0（Phase 1）。この文書を追加してもバージョンは上げていない
- 位置づけ: 受託として販売できる状態までの課題と計画。実装の正本はコード、運用判断の正本はこの文書
- 法的位置づけ: 医療広告の記述は社内のリスク整理であり、法律意見ではない。表現を残すか変えるかは、案件の責任者と広告に詳しい有資格者の確認を経る

このファイルは `public/` の下にある。`main` へマージすると、Firebase Hosting の本番へ一緒に載る。社外に出したくない場合は、マージ前に `public/` の外へ移すか、Hosting の ignore に含める。

## 1. 調査方法

コード、既存の書き出し結果、本番 URL の応答を確認した。

- `extract.py` / `render.py` / `template.html` / `brands/*/brand.json` / `HANDOVER.md` / `README.md` を読んだ
- `out/` の MP4 を ffprobe し、代表時刻のフレームを切り出して画素を測った
- 本番の `https://cc-dev-ps7.web.app/cm-generator/` 配下に HTTP で到達できるかを確認した
- 比較対象の社内標準は、アプリ開発標準 v1.1.0（2026-09-26）と Web アプリケーションセキュリティ標準 v1.0.0（2026-10-05）

やっていないこと:

- `k-dc.net` の再取得。既存の `brands/kdc/` を上書きするため
- MP4 の再レンダー。この環境には Noto Sans JP も IPAGothic もなく、再レンダーすると納品済みの絵が変わる
- Playwright による新規書き出し。既存 MP4 が、現行テンプレートで一度は書き出せた証拠としてある

## 2. いまできていること

URL から `brand.json` を作り、15秒・30秒 × 横 1920×1080・縦 1080×1920 の4本を、H.264 / yuv420p / 30fps / 音声なしで書き出す経路はある。テンプレートの描画は `seek(t)` にまとまっていて、同じ `brand.json` と同じフォントなら絵の手順は決定的である。

実績として、新小岩こばやし歯科クリニック（`brands/kdc/`）の4本が `out/kdc-{15,30}s-{h,v}.mp4` にある。hihaho はアイコンと文字を分けた基準データで、同じく4本ある。ffmpeg は引数配列で呼んでおり、API キーは環境変数である。

受託の商品として足りないのは、公開範囲、終盤のロゴの見え方、業種ごとの表現確認、同じ結果を別の機械で出すこと、テスト、納品の記録である。

### C01 成果物が本番に出ている

`firebase.json` の Hosting `main` は `public` ディレクトリ全体を配信する。ignore はドットファイルと `node_modules` だけで、`cm-generator` は除外されていない（`firebase.json:14-19`）。`main` への push で live チャンネルへデプロイする（`.github/workflows/firebase-hosting-merge.yml:6-8` と `:36-43`）。

2026-10-15 に次へ到達できた。

| URL | 応答 |
|---|---|
| `/cm-generator/out/kdc-15s-h.mp4` | 200、`video/mp4`、467,747 バイト、`cache-control: max-age=3600` |
| `/cm-generator/brands/kdc/brand.json` | 200、`application/json`。医院名、コピー、ロゴの取得元 URL を含む |
| `/cm-generator/template.html` `/extract.py` `/HANDOVER.md` | 200 |

`Last-Modified` は 2026-10-07。HTML には `Cache-Control: no-cache` が付く（`firebase.json:71-79`）。MP4 と JSON は約1時間キャッシュされる。応答には HSTS があった。Content-Security-Policy、`X-Content-Type-Options`、`frame-ancestors`、Referrer-Policy、Permissions-Policy はこの応答には無かった。

HANDOVER は「未デプロイ」と書いていた。文書の先頭に訂正を足してある。中身のチェックリストは 2026-10-03 の作業メモとして残している。

医院名そのものは医院サイトで公開されている。ここで外に出ているのは、CM の絵、採用したコピー、ロゴファイル、ツールのソースである。未公開の提案映像が CDN に載る状態は、受託の納品物の置き場として使えない。

### C02 白カード上のロゴ

終盤は背景を `colors.fg`（kdc では `#f7fafb`）で塗り、その上にロゴを描く（`template.html:140-155`）。ロゴを暗い背景へ戻す処理はない。

`brands/kdc/full.png` は 1285×315 の RGBA。不透明画素の平均色は RGB(254, 143, 20)。白に近い不透明画素は無く、見える部分はオレンジ系だけである。`#f7fafb` とのコントラスト比は **2.18:1**。アクセント `#f89818` と白文字 `#f7fafb` は **2.11:1**。WCAG の AA は、大きな文字で 3:1、通常の文字で 4.5:1 を目安にする。CM の法的義務ではないが、医院名の小さい行が溶ける明るさである。

15秒横の 11秒フレームでは、ロゴ帯（おおよそ y=368–576）にオレンジの画素があり、タグラインは y=692–760 の暗い文字、サブコピーは y=812–848 の灰色だった。サブコピー `#8a9aa3` と白の比は **2.77:1**。hihaho のサブ色 `#7fa3b0` だけは `#4f7080`（約 5.05:1）へ置き換わる（`template.html:146`）。kdc の `#8a9aa3` はその例外に入らない。

4本とも同じテンプレートなので、横も縦も終盤は同じ組み合わせである。強いメッセージの場面は白文字をアクセント色の全面に載せる（`template.html:111-120`）。kdc の 3秒フレームでは文言は読めた。大きい文字なので実用上は見えるが、コントラストを検査してから書き出す処理はない。

### C03 医療広告として危ない表現を止められない

`brands/kdc/brand.json` のコピーには、次が入っている。

- `words`: 「痛くない」「疲れない」「抜かない」（`:21-25`）
- `words2`: 「年中無休で診療」「夜19時まで受付」「50名以上の歯科医師」（`:26-30`）

15秒横の 5.5秒付近と、30秒横の 12秒付近のフレームは、この文言と一致していた。`needs_review` は `false`（`:41`）なので、このファイルは再書き出しが通る。

医療法の広告規制と、厚生労働省の医療広告ガイドラインでは、広告できる事項は限られる。ウェブサイトは条件を満たすと表示できる範囲が広がるが、虚偽、比較して優れていると示す表現、誇大、客観的に証明できない内容は、そのあとでも認められない。「痛くない」「疲れない」「抜かない」は、患者全員に当てはまる効果のように読める。人数・年中無休・受付時刻は事実の主張で、いつの情報か、常勤かどうか、休診日の例外があるかが `brand.json` に残っていない。終盤に出るのは CTA、URL、サブコピーの地域と医院名で、電話番号と番地はない（`template.html:157-158`、`brand.json:37-39`）。

ツール側には業種の区別、禁止しやすい語の警告、根拠の添付欄、確認者の名前がない。モデルへのプロンプト（`extract.py:213-216`）も、医療広告の条件を渡していない。

この計画では、既存4本の文言は変えていない。変えるかどうかは医院と確認者の判断である。

### C04 確認の記録がない

以前の `extract.py` は、API キーがあると `needs_review` を `false` にしていた。`render.py` はそのフラグを見ていなかった。README は「true の間は手直し必須」と書いており、実装と違っていた。

今回のブランチで、新規の取得は常に `needs_review: true` にし（`extract.py:245`）、`render.py:11-12` は true の間書き出さないようにした。`--force` で意図的に通せる。sylavids は true のままなので、テストが「force なしでは止まる」ことを見ている。

kdc はもともと false である。誰が、いつ、どの項目を見た結果 false にしたのかはファイルにない。`--force` を使ったこともログに残らない。受託の納品では、確認者・日付・確認した項目・`brand.json` のハッシュが要る。

### C05 同じ絵を再現できない

- `requirements.txt` もロックファイルもない。README は `pip install playwright pillow anthropic` のみ（`README.md` のインストール行）
- フォントは実行環境のものを探す（`template.html:19`、太字 900 は `:47`）。HANDOVER は、サーバーが太字のない IPAGothic、Mac が Hiragino の太字、と書いている。調査環境の日本語フォントは WenQuanYi Micro Hei と Droid Sans Fallback で、指定スタックの実体は無かった
- 既存の `brand.json` には、取得日時、HTML のハッシュ、モデル名、プロンプト、フォント名、テンプレート版が入っていない。新規取得だけ `generator` と `copy_source` を足す（`extract.py:240-243`）
- モデル名は `claude-sonnet-4-6` 固定（`extract.py:218`）。温度の指定はなく、応答は正規表現で最初の `{...}` を抜く（`:221`）。HANDOVER のチェックリストでは、この API 経路は未テストのまま
- MP4 にテンプレート版は入っていない。`render.py:143-145` の ffmpeg オプションにメタデータも faststart もない

### C06 テストがない状態から、ガードだけ足した

このブランチの前に、cm-generator の自動テストは無い。CI も、speech-dashboard 用のワークフローがあるだけで、このツールは対象外である。

追加した `tests/test_safety.py` は、slug、URL の拒否、ロゴパス、出力ファイル名、`needs_review`、尺と向き、だけを見る。ブラウザもネットワークも使わない。次はテストしていない。

- `cut()` の途中切断（sylavids の実例）
- 字数上限
- コントラスト
- 30秒の三点が画面内に収まること
- `words` が空のときの `template.html:127`（`PAGES.length` で割る）。`render.py` は空の `words` を書き出し前に止めるが、テンプレート自体はそのまま

### C07 URL 取得の残り

`extract.py:31-74` は、http(s) 以外、URL 内のユーザー情報、localhost、`.local` / `.internal`、メタデータ用ホスト名、数字だけのホスト、私設・ループバック・リンクローカル・予約アドレスを拒否する。リダイレクト先も同じ検査を通し、応答は 8,000,000 バイトで切る。

残っているもの:

- 名前解決のあと、接続の瞬間にアドレスが変わる場合までは見ていない（`extract.py:34` のコメント）
- ロゴ候補の失敗は種類を残さず次へ進む（`extract.py:140-143`）。SVG は最初から除外（`:131`）
- サイトの利用条件や robots は見ない
- オペレーターが自分の機械で公開 URL を取る分には、被害は自分の実行環境に限られる。これを Web の入力にすると、セキュリティ標準 3.9 の SSRF がそのまま攻撃面になる。そのときは、接続時の再検証、Egress 制限、応答サイズと時間の制限、リダイレクト回数の制限を重ねる

### C08 失敗が成功に見える

- 画像の `onerror` でも `READY` が解決する（`template.html:26`）。ロゴが読めなくてもフレーム撮影は続く
- `page.evaluate("window.READY")`（`render.py:135`）にタイムアウトが無い
- モデルが `words` を文字列で返しても、`extract.py` は形を検査せず JSON を書く。`render.py` の形検査で書き出しは止まる
- ロゴ候補の例外は捨てる（C07）
- Claude 失敗時は例外の型名だけを出す（`extract.py:223-225`）。キーそのものは出さない
- フレーム用の一時ディレクトリは `finally` で消す（`render.py:150-152`）。プロセスを強制停止した場合は残る

### C09 書き出し品質の残り

測定値（`out/kdc-15s-h.mp4` と `out/kdc-30s-h.mp4`）:

| 項目 | 15秒横 | 30秒横 |
|---|---|---|
| 尺 | 15.000 秒 | 30.000 秒 |
| サイズ / ピクセル | 1920×1080、yuv420p、30fps | 同左 |
| ビットレート | 249,465 bps | 203,271 bps |
| 音声 | なし | なし |
| moov | mdat の後ろ | 同じ作り |

音声なしは README の既知事項のまま。フラットな図形なら 200kbps 台でも荒くは見えない。色差 4:2:0 は、彩度の高い文字の縁をにじませる。`-movflags +faststart` が無いので、moov はファイル末尾にある。ファイルが 500KB 前後なら待ちは小さい。

30秒のロゴ場面は拍 28 から 50 で、約 11 秒ある（`template.html:32`）。補足三点は拍 `s+9.5` 以降、時刻で約 18.75 秒から出る（`:148`）。18秒のフレームには三点がまだ無く、23.5秒の横と縦には三点が画面内に見えた。はみ出しの再発を止める自動検査は無い。過去の見切れ修正（コミット `72fd9a6`）は、テストが無いので戻しうる。

hihaho のアイコンは 200×200（パレット PNG、約 2.7KB）で、横のロックアップでは高さ 334px に拡大する（`template.html:78`）。HANDOVER が書いている解像度不足はそのままである。

### C10 字数ルールが三種類

| 場所 | l1b / l2b | words | tagline |
|---|---|---|---|
| HANDOVER の目安 | 6字 | 9字 | 16字 |
| プロンプト `extract.py:214` | l1b/l2b は 6字 | 9字 | 16字 |
| 実装の上限 `extract.py:196` | l1b 8 / l2b 8、l2a は 10 | 10字 | 18字 |

実装の方が長い。プロンプトを守っても、`sanitize()` はより長い文字列を通す。

仮コピーの実例が `brands/sylavids/brand.json` にある。「誰に、何を届」「時間を埋めるのでは」のように文の途中で切れている（`:19-37`）。`needs_review` は true で、`out/` に sylavids の MP4 は無い。

### C11 権利とライセンス

リポジトリに `LICENSE` は無い。次のファイルが、利用許諾のメモなしで入っている。

- `brands/kdc/full.png` と `logo_source`（医院テーマ内の URL、`brand.json:15`）
- `brands/sylavids/full.png`
- `brands/hihaho/` のロゴ（自社ブランドでも、利用条件の記録は無い）

フォントファイルは同梱していない。映像に焼き付いた字形の再配布と、商用案件でそのフォントを使ってよいかは、フォントごとの条件による。Noto Sans JP（OFL）を同梱して、それ以外に落ちないようにするのが、再現と権利の両方で明確である。

モデルが書いたコピーの帰属は、API の契約と顧客との契約で決まる。`brand.json` にはその区別が無い。

### C12 文書が古かった

HANDOVER は作業ブランチが main 未マージ、Hosting 未デプロイ、k-dc.net は未確認、と書いている。kdc の追加コミット `19c574c`（2026-10-03）は `origin/main` の祖先で、本番のファイル更新時刻は 2026-10-07 である。文書の先頭で訂正し、詳細はこの計画に寄せた。

バージョン文字列は HANDOVER の文章と、新規取得時の `GENERATOR_VERSION`（`extract.py:8`）だけである。画面、レジストリ、MP4 の間で揃える対象がまだ無い。

### C13 社内標準との差

cm-generator は React の利用者向けアプリではない。操作画面は無く、描画用の `template.html` と、ローカルで動かす Python がある。開発標準の「全アプリ共通 UI」は、その画面を作る時点の要件である。今の公開物は、画面が未整備の静的ファイルである。

| 標準の項目 | 状態 |
|---|---|
| 共通ヘッダー、版数、取扱説明書、リリースノート、目安箱 | 操作画面が無いので未実装。公開 URL にも案内は無い |
| バージョンの一致（表示、Apps、ChangeLog、リリースノート） | v0.1.0 は HANDOVER の文章のみ。Apps への登録は無い |
| Firestore へのクライアント直接書き込み | このツールは Firestore を使っていない |
| 利用者向け画面に内部エラーを出さない | CLI は失敗時に Python の終了メッセージを出す。Web のエラー画面は無い |
| Phase | 文書上は Phase 1。標準の Phase 3（本番、監視、セキュリティ、バックアップ、利用者向け説明）には達していない |
| 目安箱のサーバー経由、App Check、レート制限 | 未実装。送る機能も無い |
| 管理画面の認証 | ツールに管理画面は無い。Hosting 上のファイルは誰でも取れる（C01） |
| セキュリティヘッダー | 調査した HTML 応答は Cache-Control と、Firebase 側の HSTS。CSP 等は無い |
| 依存のロック、秘密の分離 | ロック無し。API キーは環境変数で、リポジトリには無い |
| 正常系と負のセキュリティテスト | ガードの単体テストのみ（C06） |
| AI 出力を未検証で採用しない | 新規取得は `needs_review: true`。既存 kdc は false のまま（C03、C04） |

セキュリティ標準のうち、いまの CLI に既に関係するものは次のとおり。

- 任意 URL は信頼しない入力である（3.9）。公開 http(s) への制限を入れた。接続時の再検証は未了（C07）
- 利用者にファイルパスを指定させない（3.5）。ロゴは brand ディレクトリ内だけを読む（`render.py` の `resolve_inside`）
- コマンドはシェルを介さない（3.5）。ffmpeg は配列のまま
- モデル出力を HTML やシェルとして実行しない（3.17）。コピーは Canvas の `fillText`。JSON を `add_init_script` に埋め込むので、Web ページの入力にするときは別の検査が要る
- 秘密をログに残さない（3.12）。Claude 失敗時は例外の型名だけ
- 外部応答の全フィールドをそのまま返さない、という段までは行っていない。取得 HTML から正規表現で抜いた値を `brand.json` に書く

画面、アカウント、Firestore、課金を足すときは、標準の設計メモ（データ、主体、認可、エンドポイント、信頼境界）を先に書き、共通ヘッダーと目安箱とレジストリをその範囲で実装する。CLI の受託制作のままにするなら、その範囲は「対象外」と案件資料に書く。

### C14 テンプレートをブラウザで直接開く

`template.html:10` は `window.BRAND` が既にある前提である。Hosting 上の HTML を開くと、そこで例外になる。顧客向け画面ではない。C01 を閉じれば、この URL 自体が無くなる。

## 4. 優先度付き改善計画

工数は実働の目安であり、暦の日程ではない。短期が終わるまで、無人で回る商品としては売らない。短期の完了条件を満たせば、人が確認する受託制作としては次の案件に入れる。

既存の kdc 4本の文言と、本番からの取り下げは、このブランチでは行っていない。マージしても Hosting の配信対象は減らない。

### 4.1 短期 — 次の案件の前

| 順 | 内容 | 工数目安 | 完了条件 |
|---|---|---|---|
| S1 | 納品物を Hosting と公開ツリーから外す | 0.5人日 | `out/` と `brands/` の顧客素材が本番 URL で 404 になる。共有が必要なら、認証のある別経路を使う。この計画書を公開したくない場合は、同じ対応に含める |
| S2 | フォントを Noto Sans JP に固定し、依存をロックする | 1人日 | 手順どおりの環境で、同じ `brand.json` から再書き出ししたフレームの文字幅が、記録した基準と一致する。使用フォント名が `brand.json` に残る |
| S3 | 白カードとロゴのコントラスト | 1.5人日 | ロゴを載せる面とロゴのコントラストが 3:1 未満なら、書き出しを止めるか、暗い板・縁取り・単色化のいずれかを自動で選ぶ。kdc 4本を再書き出しし、横縦それぞれの終盤で医院名が読めることを目視の記録に残す。S2 のあとに行う |
| S4 | 納品チェックリスト | 1人日 | 案件ごとに、確認者、日付、確認項目（文言、権利、コントラスト、尺、音声の有無）、`brand.json` のハッシュがファイルで残る。`needs_review` を false にした記録と一致する |
| S5 | 歯科案件の表現確認 | 0.5人日と、有資格者の確認 | 「痛くない」「疲れない」「抜かない」と、人数・診療時間を残すなら、根拠と限定の文言を記録する。残さないならコピーを差し替えて再書き出しする。ツールは語を自動削除しない |
| S6 | 取得の失敗を見えるようにする | 1人日 | ロゴ候補を捨てた理由が `brand.json` に残る。接続直前のアドレスでも私設アドレスを拒否する。テストを足す |

### 4.3 売れる状態

次が揃ったときを、受託制作として売れる状態とする。

- 顧客素材が、認証の無い Hosting に無い
- 納品した MP4 で、ロゴの医院名が終盤の背景の上で読める
- 医療・健康の案件は、確認者の記録が無いと `needs_review` を外せない
- フォントと依存を固定した環境で、同じ `brand.json` から同じレイアウトを再出力できる
- ガードとレイアウトのテストが、手元で再実行できる
- ロゴとフォントとコピーの利用条件が、案件メモに残っている

Web アプリとして標準の受入条件（共通ヘッダー、目安箱、Developer Console、Phase 3）まで満たすのは、M8 をやるときである。それより前に「公開アプリ」としては売らない。

## 5. このブランチで入れたもの

計画が本体である。挙動を変えたのは、次の安全側のガードだけである。見た目のテンプレート、既存の `brand.json`、既存の MP4、Hosting の ignore は変えていない。

| 変更 | 場所 |
|---|---|
| http(s) と公開アドレス以外の URL を拒否。応答サイズ上限。リダイレクトも再検査 | `extract.py` |
| slug を英小文字・数字・ハイフンに制限 | `extract.py` の `safe_slug` |
| 新規取得は常に `needs_review: true`。`copy_source` と `generator` を書く | `extract.py` |
| true の間は書き出さない。`--force` で明示的に通す | `render.py` |
| ロゴの読み取りを brand ディレクトリ内に限定。出力ファイル名からパス区切りを除く | `render.py` |
| 空のコピー、不正な尺・向き・fps、ffmpeg 不在を、撮影の前に止める | `render.py` |
| 上記の単体テスト 8件 | `tests/test_safety.py` |

確認: `python3 -m unittest discover -s tests` は 8件成功。Playwright での再レンダーは行っていない。

新規取得の `needs_review` が常に true になるので、API キーがあっても、人が false にするか `--force` を付けるまで MP4 は出ない。既存の kdc（false）と hihaho（項目なし）は、これまでどおり書き出し対象である。
