# EMLポスト セキュリティ設計

- 守るデータ: 利用者が読み込むEML本文、ヘッダー、添付ファイル
- 主体: 匿名利用者のみ。認証・管理機能・サーバーAPIなし
- 信頼境界: EMLは信頼しない入力。ブラウザ内でのみ解析し、サーバーへ送信しない
- 入力制約: `.eml` / `message/rfc822`、1ファイル、最大50MB、ヘッダー最大1MB、MIMEパート最大600、ネスト制限あり
- 出力: TXTダウンロード、印刷PDF、添付ファイル個別ダウンロード
- XSS対策: メール由来データはすべて `textContent` / `value` で表示し、HTML本文をDOMへ挿入しない
- 永続化: EML内容をCookie、LocalStorage、IndexedDB、Firestore、ログへ保存しない
- 通信: 同一オリジンの静的ファイル取得のみをCSPで許可
- 想定する誤用: 巨大ファイル、深いMIMEネスト、破損EML、危険なHTML、実行形式の添付
- 回復: 解析失敗時は副作用なく停止し、ファイルを再選択できる

## エンドポイント

サーバーAPIは使用しない。Firebase Hostingから静的ファイルを配信するだけである。
