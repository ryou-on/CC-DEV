## 0. この文書の目的

本サービスの最大の法務リスクは、**未成年を含む個人の顔写真を、海外の第三者3D生成APIに送信する**ことである。このリスクを潰すには、「規約に書いてある」だけでは足りず、**誰が・いつ・どの版の何に同意したかを、後から証明できる状態**にしておく必要がある。本文書はそのための運用とデータ設計を定める。

### 押さえるべき法的要件（3点セット）

| # | 要件 | 根拠 | 本サービスでの対応 |
|---|---|---|---|
| 1 | 外国にある第三者への個人データ提供について、移転先国名・当該国の制度・移転先の保護措置を情報提供したうえで**本人の同意**を得る | 個人情報保護法 第28条第2項 | 注文フォームで**独立した必須チェックボックス**（後述 A-3） |
| 2 | **16歳未満**の個人情報については**法定代理人の同意**を得る | 令和8年改正個人情報保護法（令和8年7月10日成立）。【要確認：施行日】 | 被写体年齢の申告＋保護者同意のチェックボックス／園ルートは書面同意書 |
| 3 | 通信販売における**返品特約**を、他の事項より明瞭に表示する | 特定商取引法 第15条の3、返品特約表示ガイドライン | 決済ボタン直上に赤枠で常時表示（後述 A-6） |

### 設計の基本原則

1. **同意はバンドルしない。** 「規約とプライバシーポリシーと外国移転と広告利用にまとめて同意」は不可。**目的ごとにチェックボックスを分ける。**
2. **必須と任意を明確に分ける。** 任意（広告利用）は初期状態オフ、チェックしなくても購入完了できること。
3. **プレチェック（初期状態オン）禁止。** すべて未チェック状態から利用者が能動的にチェックする。
4. **同意した版を記録する。** 規約・ポリシーはバージョン番号（例 `pp-v1.0` / `tos-v1.0`）で管理し、同意ログに版を残す。
5. **撤回導線を必ず用意する。** 同意の撤回・削除請求は、問い合わせフォームだけでなく注文完了メールにもリンクを載せる。

## 1. Webサイト上の同意チェックボックス（確定文言）

> **この節の文言が最終版である。**他担当が先に実装したチェックボックス文言がある場合は、**本節の文言で上書きすること。**
> 実装場所：`/public/mini-me/` の注文フォーム（決済ボタンの直上）

### 配置順と表示仕様

```
┌─ 【ご確認とご同意】─────────────────────────┐
│  A-1 ☐ 規約・プライバシーポリシー   （必須）      │
│  A-2 ☐ 写真の権利・被写体の同意     （必須）      │
│  A-3 ☐ 海外への画像送信             （必須）★重要 │
│  A-4 ☐ 被写体の年齢と保護者同意     （必須）★重要 │
│  A-5 ☐ AI生成物であることの理解     （必須）★重要 │
│  ────────────────────────────────  │
│  A-6 【返品特約】赤枠・常時表示（チェックではない）  │
│  ────────────────────────────────  │
│  A-7 ☐ 作品写真のSNS等への掲載      （任意）      │
│  A-8 ☐ お得な情報のメール受信       （任意）      │
└──────────────────────────────────┘
             [ この内容で注文する ]
```

- ★重要マークの3項目は、背景色 `--sand` のボックスで囲み、他より視覚的に強調する
- A-1〜A-5 がすべてチェックされるまで、注文ボタンは `disabled`
- A-7・A-8 は初期状態オフ。オフのままでも注文可能
- リンク（規約・ポリシー）は別タブで開く（`target="_blank" rel="noopener"`）

### A-3【必須★】外国にある第三者への提供

> **本チェックボックスは個人情報保護法第28条の同意である。単独で独立させ、他の同意と絶対に束ねないこと。**

```
☐ 3Dモデルを作るため、アップロードした写真が【要記入：国名】にある
　 【要記入：委託先事業者名】社のサーバーへ送信されることに同意します。

　 ▸ 送信するもの：アップロードした写真
　 ▸ 送信先の国　：【要記入：国名】
　 ▸ 送信の目的　：3Dモデルの生成のみ
　 ▸ その国の個人情報保護制度について ▶ 詳しく見る（アコーディオンで展開）
　 ▸ 送信先が講じる保護措置について　 ▶ 詳しく見る（アコーディオンで展開）
　 ▸ AIの学習には使用されません。生成完了後、送信先のサーバーから削除されます。
```

**アコーディオン内に表示する内容**は、プライバシーポリシー第7条 7-2 および 7-3 の本文をそのまま転記する。**リンクで飛ばすだけでなく、その場で読める形にすること**（同意画面から離脱させない）。

**同意しない場合の表示：**
```
この同意がない場合、3Dモデルを作成できないため、ご注文いただけません。
```

## 1-2. 現状実装とのギャップ（`public/mini-me/index.html` 2026-07-29 時点）

現在の実装には**必須チェックボックスが2つしかなく、法令要件を満たしていない。**下表のとおり修正すること。

| 現状 | 問題 | 対応 |
|---|---|---|
| `#consent1`「アップロードした写真が第三者の3Dモデル生成サービス（海外サーバーを含む）に送信されることに同意します」 | **28条の情報提供義務を満たさない。**「海外サーバーを含む」だけでは、①国名 ②当該国の制度 ③移転先の保護措置 が示されていない | 本文書 **A-3** の文言に差し替え。アコーディオンでポリシー第7条 7-2・7-3 を展開表示する |
| `#consent2`「被写体本人（未成年の場合はその保護者）の同意を得ています」 | 写真の**著作権**についての表明保証がない。年齢の申告項目もない | **A-2**（権利＋被写体同意）と **A-4**（年齢申告＋保護者同意）の2つに分割 |
| 規約・ポリシーへの同意チェックがない | 契約の成立要件として不十分 | **A-1** を追加 |
| AI生成物であることの理解チェックがない | 「似ていない」クレームに対する最大の防御線が欠落 | **A-5** を追加 |
| 返品特約の明瞭表示がない | 特定商取引法第15条の3の要件を満たさず、**到着後8日間は返品を拒めなくなる** | **A-6** を決済ボタン直上に赤枠で追加 |
| 同意の記録が保存されていない（`updateGenButton()` でボタン活性化しているだけ） | 「同意を得た」ことを後から証明できない | 第2節の `consents` コレクションに記録する Functions を実装 |

さらに、`index.html` のFAQ内「保護者の方の同意があればご利用いただけます」（817〜821行付近）の記述は、**16歳未満は法定代理人の同意が必須**である旨に書き換えること。

## 2. 同意記録のデータ設計（Firestore）

### 2-1. コレクション構成

```
consents/{consentId}
```

| フィールド | 型 | 内容 |
|---|---|---|
| `consentId` | string | 自動採番（ドキュメントID） |
| `orderId` | string | 紐づく注文ID（注文前同意の場合は null → 注文確定時に更新） |
| `subjectType` | string | `"self"` \| `"guardian_web"` \| `"guardian_paper"`（園ルート書面） |
| `consenterName` | string | 同意した人の氏名 |
| `consenterEmail` | string | 同意した人のメールアドレス |
| `subjectAgeBand` | string | `"16plus"` \| `"under16"` |
| `items` | map | 同意項目ごとの真偽値（下表） |
| `docVersions` | map | `{ terms: "tos-v1.0", privacy: "pp-v1.0", overseas: "ovs-v1.0" }` |
| `consentedAt` | timestamp | サーバータイムスタンプ（クライアント時刻は使わない） |
| `ipAddress` | string | 同意時のIPアドレス |
| `userAgent` | string | 同意時のUA文字列 |
| `overseasRecipient` | map | `{ vendor: "...", country: "...", asOf: "2026-07-29" }` 同意時点の移転先情報のスナップショット |
| `paperFormRef` | string | 園ルートの場合、スキャンした同意書のStorageパス |
| `schoolId` | string | 園ルートの場合、園のID |
| `revokedAt` | timestamp \| null | 撤回された日時 |
| `revokeReason` | string \| null | 撤回理由 |
| `deleteExecutedAt` | timestamp \| null | 撤回に伴うデータ削除の完了日時 |

`items` の中身：

```json
{
  "terms": true,
  "privacy": true,
  "imageRights": true,
  "overseasTransfer": true,
  "guardianConsent": true,
  "aiQualityUnderstood": true,
  "selfAge16plus": true,
  "snsPublication": false,
  "newsletter": false
}
```

### 2-2. 記録のルール

1. **書き込みはCloud Functions（asia-northeast1）経由のみ。**クライアントから `consents` への直接書き込みは Firestore セキュリティルールで禁止する。改ざんを防ぐため。
2. **更新禁止（追記のみ）。** 同意内容の変更は新しいドキュメントを作成する。`revokedAt` / `deleteExecutedAt` のみ後から書き込みを許可する。
3. `consentedAt` は必ず `FieldValue.serverTimestamp()` を使う。
4. **`overseasRecipient` は同意時点のスナップショットを保存する。**委託先を変更した場合、過去の同意は新しい委託先への提供を正当化しない。委託先変更時は、既存顧客に対して再同意を取得する運用が必要（プライバシーポリシー第13条）。
5. 保存期間：**取引終了日から5年**（プライバシーポリシー第4条4-4）。自動削除バッチで期限切れを削除する。

### 2-3. 同意版の管理

規約・ポリシーの版は、Firestore の `legalDocs/{docId}` に本文とバージョン、公開日を保存し、**版を更新したら過去版もイミュータブルに保持する**。「どの版に同意したか」を後から復元できることが監査上重要。

```
legalDocs/tos-v1.0   { type: "terms",    body: "...", publishedAt: ..., supersededAt: ... }
legalDocs/pp-v1.0    { type: "privacy",  body: "...", publishedAt: ..., supersededAt: ... }
legalDocs/ovs-v1.0   { type: "overseas", body: "...", publishedAt: ..., supersededAt: ... }
```

### 2-4. データ自動削除の実装

プライバシーポリシー第4条4-4で約束した保存期間は、**約束しただけでは意味がない。実装で担保すること。**

| 対象 | 期限 | 実装 |
|---|---|---|
| アップロード画像原本 | 生成完了+30日 | Cloud Scheduler → Functions で日次バッチ。Storage オブジェクトにカスタムメタデータ `deleteAfter` を付与し、それを走査 |
| 3Dモデルデータ | 発送完了+180日 | 同上 |
| 同意記録 | 取引終了+5年 | 同上 |
| 削除実行ログ | 削除実行から3年 | 削除したことの証跡として `deletionLogs` に残す |

**削除は論理削除ではなく物理削除。**削除完了後、`deletionLogs/{id}` に `{ target, orderId, executedAt, method }` を記録する。

## 4. 同意の撤回・削除請求のフロー

```
[受付] メール / 問い合わせフォーム / 園経由
   ↓
[本人確認] 注文番号 + 注文時メールアドレスの一致を確認
   ↓        （園ルートは同意書の署名者氏名 + 園名で照合）
[工程確認] 製造工程開始前？
   ↓ YES → 注文キャンセル・全額返金・データ即時削除
   ↓ NO  → 製造完了後にデータ削除。返金は個別協議
   ↓
[削除実行] 画像・3Dモデル・プレビューデータを物理削除（7営業日以内）
   ↓        委託先にも削除を要求し、削除完了の確認を取る
   ↓
[記録] consents.revokedAt / deleteExecutedAt を更新
   ↓    deletionLogs に証跡を残す
   ↓
[通知] 削除完了をメールで連絡
```

**注意：** 注文情報（氏名・住所・金額）は帳簿保存義務があるため、削除請求があっても法定保存期間中は削除できない。この点を削除完了通知に明記すること。
